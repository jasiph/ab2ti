## 2. Defects discovered

Demonstrated issues fixed in this phase:

1. **Static `public/robots.txt` allowed all paths** (`Disallow:` empty). Admin, account, capability, and auth prefixes were only protected by meta robots.
2. **No sitemap.** Phase 2A deferred `sitemap.xml`; Phase 4D required eligibility-aware inclusion/exclusion.
3. **Informational SEO titles were hardcoded Indonesian**, so English locale still advertised “Teknologi Tani”, “Publikasi AB2TI”, “Lapak Anggota AB2TI”, and “Keanggotaan AB2TI” in crawler-visible meta.
4. **English Knowledge/landing copy still used the Indonesian product label** (“Teknologi Tani article list”, “Back to Teknologi Tani”, homepage fallback sentences).
5. **Publishing archive H1 hardcoded `Publikasi`**, ignoring `$t('Publications')`.
6. **Language switcher mixed hardcoded `Change to:` / `Ganti ke:`** and left a `console.log` in the public UI.
7. **Mobile menu button always announced “Open main menu”**, including when the menu was open.
8. **Hero `button_url` / Welcome `cta_url` were passed through unsanitized**, so a `javascript:` or `data:` value could reach the homepage CTA.

Observed and **not** treated as product defects:

- `/about` and `/contact` 404 until active CMS pages with those slugs exist (operational content, not a second CMS).
- Publication type labels (`Berita`, `Kegiatan`, …) remain established Indonesian product terms on URLs and chips.
- Official organization name stays Indonesian in both locales.
- Owner/admin/capability contracts from 4C and site-access provisioning are unchanged.

## 3. Corrections made

- Replaced static `public/robots.txt` with Laravel `GET /robots.txt` so `Sitemap:` uses `CanonicalUrl` origin and Disallow rules can be tested.
- Added `GET /sitemap.xml` generated by `PublicSitemap` using existing `published()`, `publicEligible()`, and active CMS queries (no duplicate eligibility rules).
- Hub SEO titles/descriptions now go through `__()` and existing JSON keys after `SetLocale`.
- English Knowledge/landing strings use **Agricultural Technology**; official org name unchanged.
- Homepage CTA hrefs and CMS related links share `SafePublicHref`.
- Navbar open/close name, language-switcher label key, Publishing hub heading localization.

## 5. SEO / indexability result

Canonical stack is still `PublicMetadataInput` → `PublicMetadataResolver` (server-side `<Head>` / Blade meta, not client-only). No per-feature SEO system was added.

| URL class | Title / description | Canonical | OG / Twitter | robots |
|---|---|---|---|---|
| Home, CMS, hubs | Localized hub copy or editorial fields | Absolute origin | `website` or `article` | `index, follow` |
| Publication / Knowledge detail | Resource SEO fields, excerpt, body plaintext | Resource path | `article` | Only if published |
| Lapak / Listing detail | Storefront/listing copy | Resource path | `website` | Only if public-eligible |
| Intake, `/akses`, `/akun`, `/admin`, login | Generic / site default | Path | Default OG image | `noindex, nofollow` |
| Errors | Phase 2E copy | Request path | Default | `noindex, nofollow` |

Query strings are stripped from canonical URLs (`CanonicalUrl`). Host header cannot override origin.

## 7. CMS integration result

Public CMS delivery is unchanged: `PageController` → `CmsPageViews::publicDetail()` → `EditorialContent`. Inactive pages 404. Related links now use the shared `SafePublicHref` helper instead of a private duplicate.

Homepage Hero/Welcome still come from the existing tables. Unsafe CTA schemes are dropped so the Vue fallbacks (`membership.index` / `about`) apply. Media 404s continue to omit the image rather than throwing. No second sanitizer or page-builder was added.

Block Templates, Hero admin, and File Manager remain admin-only; public rendering still consumes the stored HTML/media through the existing pipeline.

## 10. Performance observations

- Public archives already paginate (12) and map cards without admin relations. Detail pages load `media` for the current resource plus a limit-3 related set.

- No cache layer was added. No N+1 was demonstrated that required a new query architecture.
